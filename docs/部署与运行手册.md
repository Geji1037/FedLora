## 一、环境迁移改动记录

本项目最初在沐曦（MetaX）MACA 硬件平台上开发，后迁移至 **NVIDIA GeForce RTX 4090 D** GPU 环境。以下是迁移过程中所做的全部代码与配置改动。

|--------|------|------|

**说明**：基座模型从 DeepSeek-R1-Distill-Qwen-1.5B 切换为 Qwen3-1.7B，路径也从旧环境的 `/home/fedllm/` 迁移到新环境的 `/exp1/`。

**说明**：训练 Checkpoint 保存路径从旧环境的 `/home/fedllm/` 迁移到新环境的 `/exp1/FedLora/`。

### 4.1 启动训练


### 4.2 训练流程详解

整个联邦训练按 **轮次（Round）** 进行，每轮包含以下步骤：

```
                    ┌──────────────────────────────────┐
                    │        main_new.py 主循环         │
                    └──────────┬───────────────────────┘
                               │
               ┌───────────────┴───────────────────┐
               │  Round 0, 1, 2, ... (共 ROUNDS 轮) │
               └───────────────┬───────────────────┘
                               │
        ┌──────────────────────┼──────────────────────┐
        ▼                      ▼                      ▼
  ┌───────────┐        ┌───────────┐          ┌───────────┐
  │  Step 1   │        │  Step 2   │          │  Step 3   │
  │  参数下发  │        │  本地训练  │          │  LoRA聚合  │
  └───────────┘        └───────────┘          └───────────┘
```

#### Step 1：参数下发（Aggregator → Clients）

```python
params = ray.get(aggregator.distribute_parameters.remote())
```

- **首轮（冷启动）**：`params` 为空字典 `{}`，各 Client 从随机初始化的 LoRA 开始训练
- **后续轮次**：`params` 包含上一轮聚合后的全局 LoRA 权重（float32）

#### Step 2：本地训练（各 Client 并行）

```python
futures = [c.process_parameters.remote(params, round_id=rd) for c in Clients]
client_results = ray.get(futures)
```

每个 Client 内部执行以下流程：

```
Client.process_parameters(merged_lora, round_id)
    │
    ├── 1. _ensure_ready()
    │       首次调用时懒加载：
    │       ├── AutoTokenizer.from_pretrained(model_name)
    │       ├── AutoModelForCausalLM.from_pretrained(model_name, bf16)
    │       ├── get_peft_model(base_model, lora_config)  # 挂载 LoRA
    │       └── process_data(dataset_path)  # 加载 + tokenize 数据
    │
    ├── 2. 加载聚合来的全局 LoRA
    │       set_peft_model_state_dict(model, filtered, adapter_name="default")
    │       只匹配 key 名称和 shape 都一致的参数
    │
    ├── 3. 构建 Trainer 并训练
    │       make_trainer_for_steps(max_steps=global_step + steps_per_round)
    │       trainer.train()  # 训练 50 步（steps_per_round=50）
    │
    ├── 4. 持久化优化器状态（跨轮复用）
    │       self.optimizer = trainer.optimizer
    │       self.lr_scheduler = trainer.lr_scheduler
    │       self.global_step += steps_per_round
    │
    └── 5. 回传 LoRA 权重
            lora_state = {n: p for n, p in model.state_dict().items() if "lora_" in n}
            return {"lora_state": lora_state, "num_samples": len(train_dataset), "report": {...}}
```

**三个 Client 是并行执行的**（Ray 自动调度到不同节点的 GPU 上）。

#### Step 3：LoRA 权重聚合（Aggregator）

```python
global_update = ray.get(aggregator.aggregate.remote(client_results))
```

Aggregator 的聚合策略为 **FedAvg（按样本数加权平均）**：

```
                Client 1                Client 2                Client 3
                lora_state              lora_state              lora_state
                num_samples=10178       num_samples=N2          num_samples=N3
                    │                       │                       │
                    └───────────┬───────────┘───────────────────────┘
                                │
                        ┌───────▼───────┐
                        │   Aggregator   │
                        │                │
                        │  对每个 LoRA 键: │
                        │  global[k] =   │
                        │    Σ(w_i * p_i) │
                        │    ───────────  │
                        │      Σ w_i      │
                        │                │
                        │  w_i = 样本数   │
                        └───────┬───────┘
                                │
                        全局 LoRA 权重
                        (下一轮分发给所有 Client)
```

公式：

$$\theta_{global}^{(t+1)} = \frac{\sum_{i=1}^{K} n_i \cdot \theta_i^{(t)}}{\sum_{i=1}^{K} n_i}$$

其中 $K$ 为客户端数量，$n_i$ 为第 $i$ 个客户端的训练样本数，$\theta_i^{(t)}$ 为第 $i$ 个客户端在第 $t$ 轮训练后的 LoRA 权重。

### 4.3 数据加载流程

数据从 JSONL 文件加载，经过以下处理管线：

```
MedQA_EN.jsonl
    │
    ▼
process_data(dataset_path)
    │  读取 JSONL → [{instruction, input, output}, ...]
    ▼
pd.DataFrame → Dataset.from_pandas
    │
    ▼
process_func(example, tokenizer)
    │
    ├── 1. 使用 Qwen3 对话模板（qwen3_medical_en）拼接 prompt
    │       <|im_start|>system\n{instruction}<|im_end|>
    │       <|im_start|>user\n{input}<|im_end|>
    │
    ├── 2. 提取最终答案（去除 <think>...</think> 思维链部分）
    │       get_final_answer_span(output)  →  "Answer: D."
    │
    ├── 3. 拼接完整 prompt
    │       prefix_prompt + "<|im_start|>assistant\n{final_answer}<|im_end|>"
    │
    ├── 4. Tokenize + 构造 labels
    │       labels[:prefix_len] = -100   (不计算 loss)
    │       labels[prefix_len:] = input_ids[prefix_len:]  (仅监督最终答案)
    │
    └── 5. 截断到 MAX_LENGTH=2048
```

**关键设计**：只对 `</think>` 标签之后的最终答案部分计算 loss，思维链推理过程被 mask 掉（labels 设为 -100），这是一种常见的 SFT 训练策略。

### 4.4 Checkpoint 与模型保存

每个 Client 的训练 Checkpoint 自动保存到：

```
/exp1/FedLora/fed_ckpts/
├── client1/
│   ├── round-0/          # 第 0 轮训练产出
│   │   ├── checkpoint-50/
│   │   │   ├── adapter_model.safetensors   # LoRA 权重
│   │   │   ├── adapter_config.json
│   │   │   ├── optimizer.pt
│   │   │   └── trainer_state.json
│   │   └── ...
│   └── round-1/          # 第 1 轮训练产出
├── client2/
│   ├── round-0/
│   └── round-1/
└── client3/
    ├── round-0/
    └── round-1/
```

保存策略：每 50 步保存一次（`save_steps=50`），最多保留 2 个 Checkpoint（`save_total_limit=2`）。

## 六、遇到的问题与解决方案

### 6.1 Ray 打包超限（542MB > 512MB）

**报错**：
```
ValueError: Package size (542.62MiB) exceeds the maximum size of 512.00MiB.
```

**原因**：Ray 的 `working_dir="."` 会将当前目录下所有文件打包上传。`lora_output/` 目录下的 Checkpoint 文件（`.safetensors`、`optimizer.pt`）导致总体积超过 512MB 限制。

**解决**：在 `ray.init()` 的 `excludes` 中排除大文件目录：

```python
"excludes": [
    "models", "models/**",
    "lora_output", "lora_output/**",
    "data", "data/**",
    ".git", "__pycache__"
],
```

> 数据和模型文件通过绝对路径从各节点本地读取，无需通过 Ray 打包分发。

### 6.2 自定义资源未声明

**报错**：
```
Error: No available node types can fulfill resource request
  {'client_node_1': 1.0, 'CPU': 1.0, 'GPU': 1.0}
```

**原因**：`ray start` 时未声明 `client_node_1`、`aggregator_node` 等自定义资源标签。

**解决**：在 `ray start` 命令中通过 `--resources` 参数显式声明：

```bash
# Head 节点
ray start --head --port=6379 \
    --resources='{"aggregator_node": 1, "client_node_1": 1}'

# Worker 节点
ray start --address='<HEAD_IP>:6379' \
    --resources='{"client_node_2": 1}'
```

### 6.3 Aggregator 模型路径硬编码

**报错**：
```
HFValidationError: Repo id must be in the form 'repo_name':
  '/home/fedllm/models/deepseek-ai/DeepSeek-R1-Distill-Qwen-1___5B'
```

**原因**：`aggregator.py` 中的 `model_path` 还指向旧环境路径。

**解决**：将 `model_path` 更新为 `/exp1/Qwen3/Qwen3-1.7B/`。

### 6.4 Numpy/Pandas 版本不兼容

**报错**：
```
ValueError: numpy.dtype size changed, may indicate binary incompatibility.
  Expected 96 from C header, got 88 from PyObject
```

**原因**：Worker 节点上的 numpy 版本（2.x）与 pandas 编译时使用的 numpy 版本不一致。

**解决**：在**所有节点**上降级 numpy：

```bash
pip install "numpy<2.0.0" --force-reinstall
```

### 6.5 bf16 不支持

**报错**：
```
ValueError: Your setup doesn't support bf16/gpu
```

**原因**：PyTorch 未正确检测到 GPU（可能是 NVML 初始化失败），或 GPU 不支持 bf16。

**解决**：
- 确认 `nvidia-smi` 正常工作
- 确认 PyTorch 能检测到 GPU：`python -c "import torch; print(torch.cuda.is_available())"`
- 如果 GPU 不支持 bf16（如 V100/RTX 20 系列），在 `TrainingArguments` 中改为 `bf16=False, fp16=True`

### 6.6 /tmp 磁盘空间不足

**警告**：
```
file_system_monitor.cc:116: /tmp/ray/session_... is over 95% full
```

**解决**：清理 Ray 旧 session 目录：

```bash
rm -rf /tmp/ray/*
```

## 七、LoRA 配置参数说明

| 参数 | 值 | 说明 |
|------|-----|------|
| `r` | 8 | LoRA 低秩矩阵的秩 |
| `lora_alpha` | 32 | 缩放系数 $\alpha$，实际缩放倍率 = $\alpha / r = 4$ |
| `lora_dropout` | 0.1 | LoRA 层的 Dropout 率 |
| `target_modules` | `q_proj, k_proj, v_proj, o_proj, gate_proj, up_proj, down_proj` | 应用 LoRA 的注意力和 FFN 层 |
| `task_type` | `CAUSAL_LM` | 因果语言模型任务 |

可训练参数量：**8,716,288**（占总参数 1,729,291,264 的 **0.5%**）。

## 八、训练超参数说明

| 参数 | 值 | 说明 |
|------|-----|------|
| `steps_per_round` | 50 | 每轮每个 Client 训练的步数 |
| `per_device_train_batch_size` | 1 | 每 GPU 的 batch size |
| `gradient_accumulation_steps` | 4 | 梯度累积步数（等效 batch=4） |
| `learning_rate` | 3e-5 | AdamW 学习率 |
| `lr_scheduler_type` | cosine | 余弦退火调度器 |
| `logging_steps` | 10 | 每 10 步打印一次 loss |
| `save_steps` | 50 | 每 50 步保存一次 Checkpoint |
| `bf16` | True | 使用 BFloat16 混合精度训练 |
| `ROUNDS` | 2 | 联邦训练总轮数 |
| `MAX_LENGTH` | 2048 | 输入序列最大长度（截断） |
